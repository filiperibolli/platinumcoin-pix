# `load/k6` — the SLO profiles (step 47)

Three named load profiles whose **thresholds fail the run** when the platform's stated budgets break, plus
the degradation drill. The numbers they produced, and what they mean, are in
[`load/RESULTS.md`](../RESULTS.md).

| Profile | Shape | Fraud thresholds | Trace ratio | Asserts |
|---|---|---|---|---|
| `low` | ~5 TPS, 3 min | **defaults** | 1.0 | the floor: a breach here is not capacity |
| `standard` | ~58 TPS, 10 min | `loadtest` | 0.05 | the average day (5M tx/day ÷ 86,400) |
| `black-friday` | 58 → 300 → **500** → 58, ~10.5 min | `loadtest` | 0.05 | the peak, and where this host's ceiling is |
| degradation | Black Friday + an 8s rail | `loadtest` | 0.05 | that `p99 < 2s` survives a slow BACEN |

Every profile drives the same **70% send / 20% balance / 10% statement** mix.

## Run one

```bash
docker compose -f infra/docker-compose.yml up -d --build     # the stack, healthy
bash tools/k6/seed/seed-load-test-fixtures.sh                # the 200-account ring (once per `down -v`)

bash load/k6/run.sh low
bash load/k6/run.sh standard
bash load/k6/run.sh black-friday
bash load/k6/run-degradation.sh                              # 8s rail, 20% of sends external
```

`run.sh` exits with k6's own exit code: **non-zero means an SLO threshold was breached**, which is the
whole point — this is a check, not a graph. It also arms the posture each profile is defined for (fraud
thresholds, trace sampling ratio) and restores it in an `EXIT` trap, so Ctrl-C never leaves the sandbox
in a load-test configuration.

k6 runs in the `grafana/k6` Docker image with the repo bind-mounted; **no local k6 install is needed**.
The repo is mounted rather than the script piped on stdin because `lib.js` is imported by relative path,
and a script read from stdin has no directory to resolve that against.

## Overrides (for a dry run)

```bash
LOW_DURATION=30s bash load/k6/run.sh low
STANDARD_DURATION=1m STANDARD_RATE=20 bash load/k6/run.sh standard
PEAK_RATE=200 PLATEAU_RATE=120 bash load/k6/run.sh black-friday
EXTERNAL_SHARE=0.5 bash load/k6/run.sh standard      # send down the asynchronous path instead
```

Only the variables named in `run.sh`'s forwarding list reach the container — `docker run` inherits
nothing from the calling shell, and a run that silently ignored your override would be worse than one
that refused it.

## Artifacts

Written to `load/results/` (the multi-MB ones are git-ignored and regenerated by re-running):

| File | What it is |
|---|---|
| `<profile>-summary.json` | k6's own summary, every metric and sub-metric — **committed** |
| `<profile>-dependency-p99.md` | p99 per dependency for the send path — **committed** |
| `<profile>-raw.ndjson` | one line per request; re-analysable with a different threshold |
| `<profile>-<service>-{before,after}.txt` | the Prometheus scrape either side of the run, for the capacity delta |

## Files

| File | Role |
|---|---|
| `lib.js` | auth, the ring, the three verbs, the tags, the thresholds, the scenario builders |
| `low.js` · `standard.js` · `black-friday.js` | the three profiles — each one is options, nothing else |
| `run.sh` | posture + run + artifacts + restore |
| `run-degradation.sh` | the same, with mock-bacen slowed down and Σ-balances checked either side |
| `dependency-p99.js` | reads a Prometheus scrape, prints p99 per dependency |

## Relation to `tools/k6/`

`tools/k6/` is the earlier ad-hoc **correctness-under-load** pass (`docs/load/RESULTS.md`): conservation,
non-negative balance, idempotency under a retry storm, and a capacity curve. It measures with
`constant-vus` (closed model — throughput is an output) because "where does it bend" is its question.

These profiles measure with **arrival rate** (open model — throughput is an input) because "does it hold
58 TPS" is theirs. They reuse that pass's JWT minter, ring formulas and seed script rather than copying
them: the ring formulas in particular must match the seed script exactly, and two copies of a formula
that must agree is a drift bug waiting to happen.
